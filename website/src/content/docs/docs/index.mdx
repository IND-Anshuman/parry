```python
import parry
parry.install()   # every OpenAI / Anthropic call is now guarded
```

**parry** sits between your code and the SDKs you already use. It doesn't wrap
your client in a new API, ask you for a config file, or need Redis. It hooks
the SDK's own `create()` methods, so existing code keeps working, including
code inside LangChain and LlamaIndex.

## The aim

LLM apps tend to fail in the same boring, expensive ways. They pay twice for
identical prompts, hit 429 storms during batch jobs, and run up bills nobody
noticed. The fixes are well known but tedious, so every project rewrites the
same glue code, or skips it.

parry's aim is to **make the safe path the default path**:

- **Zero config.** One line at startup, with sensible defaults for every feature.
- **No rewrites.** Your call sites, types and frameworks stay exactly as they are.
- **No lock-in.** Remove the line and you're back on the plain SDK. There's no new client to migrate off.
- **No infrastructure.** Everything runs in-process. Persistence is an optional SQLite file.

## What it covers

| SDK / framework | Covered by `install()` |
|---|---|
| `openai` | `chat.completions.create`, `responses.create`, sync and async, `stream=True`, `.with_raw_response` |
| `anthropic` | `messages.create`, `beta.messages.create`, sync and async, `stream=True`, `.with_raw_response` |
| LangChain | `ChatOpenAI`, `ChatAnthropic` (they call the SDKs above), plus `ParryCallback` for anything else |
| LlamaIndex | `OpenAI`, `Anthropic` LLMs, plus `ParryHandler` for event-level guarding |

<Aside type="tip" title="Is parry right for you?">
parry is built for a single process: scripts, notebooks, eval runs, workers and
single-replica services. If several processes or hosts need to share a cache and
rate limits, put a shared cache and an API gateway in front of the provider
instead. See the [FAQ](/docs/faq/).
</Aside>
